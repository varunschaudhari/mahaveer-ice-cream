Uploaded images (item photos, gallery) are stored in `storage/uploads/` and served through a small PHP endpoint (`order/media.php?f=…`, `website/media.php?f=…`) that validates the file name, so nothing in storage is directly web-accessible. Resize uploads to max 1200 px and save as WebP (GD extension) on upload.

## 2. Runtime libraries (Composer, vendor committed)

| Package | Use |
|---|---|
| `minishlink/web-push` | Web Push to the owner's phone (needs PHP extensions openssl, curl, mbstring; gmp recommended) |
| `chillerlan/php-qrcode` | QR codes as SVG for table stickers and the takeaway poster |

Nothing else without approval. PHPUnit is **not** in composer.json; use `tools/phpunit.phar`.

## 3. Bootstrapping and paths

Every page starts with:

```php
<?php
require __DIR__ . '/boot.php';           // in a subfolder: require __DIR__ . '/../boot.php';
```

`order/boot.php` and `website/boot.php` (identical):

```php
<?php
// Locally and for order/ in production, app/ sits next to this web root.
// For website/ deployed into public_html, the deploy writes approot.php returning the real path.
$root = is_file(__DIR__ . '/approot.php') ? require __DIR__ . '/approot.php' : dirname(__DIR__);
require $root . '/app/bootstrap.php';
```

`approot.php` is generated by `.cpanel.yml` and gitignored. Being a PHP file, it prints nothing if someone requests it in a browser.

`app/bootstrap.php` defines `APP_ROOT`, loads `config.php`, `vendor/autoload.php`, a simple PSR-4-style autoloader for `app/` classes (namespace `App\`), sets `date_default_timezone_set('Asia/Kolkata')`, starts the session with secure cookie flags (HttpOnly, SameSite=Lax, Secure in production), and registers error/exception handlers that log to `storage/logs/app-YYYY-MM-DD.log` and show a friendly error page (details only when `APP_ENV=local`).

`config.example.php` keys: `APP_ENV` (local/staging/production), `APP_URL_ORDER`, `APP_URL_WEBSITE`, `DB_HOST`, `DB_NAME`, `DB_USER`, `DB_PASS`, `VAPID_PUBLIC`, `VAPID_PRIVATE`, `VAPID_SUBJECT` (mailto:), `SESSION_NAME`.

## 4. Database access

- `Db::pdo()` returns one PDO with `ERRMODE_EXCEPTION`, `FETCH_ASSOC`, `EMULATE_PREPARES=false`, and runs `SET time_zone = '+05:30'` and `SET NAMES utf8mb4` on connect.
- `Db::transaction(callable $fn)` wraps begin/commit/rollback.
- All order creation, token/bill numbering, payments and table settlement run inside one transaction.
- `SequenceService::nextToken()`: `INSERT IGNORE INTO daily_tokens (token_date, last_token) VALUES (CURDATE(), 0)`, then `SELECT last_token … FOR UPDATE`, increment, update. Same pattern for `sequences` (`bill_no`).

## 5. Money

- PHP works in **integer paise**. PDO returns DECIMAL columns as strings; convert them with string-based helpers, never through floats: `paise_from_decimal('40.00') → 4000` and `decimal_from_paise(4000) → '40.00'`.
- Display with `money(4000)` → `₹40` (no decimals when whole, else `₹40.50`).
- `PricingService` is pure (no DB) so it is fully unit-tested.

## 6. API endpoints (`order/api/`, JSON)

All responses `{ "ok": true, "data": … }` or `{ "ok": false, "error": "message_key" }`. State-changing calls are POST with `X-CSRF-Token` header (customer pages get a CSRF token in the page too). Staff endpoints require a staff session; owner-only endpoints check role.

| Endpoint | Who | Purpose |
|---|---|---|
| `menu.php` | public | Menu JSON with availability (cache 15 s) |
| `slots.php` | public | Today's pickup slots with full/available |
| `place_order.php` | public | Takeaway or table order (validated server-side by CartService) |
| `order_status.php?id&k` | public | Status for the status page |
| `table_alert.php` | public (table token) | Call staff / Request bill |
| `bulk_request.php` | public | Bulk order request |
| `poll.php?since=<id>` | staff/owner | New orders + open alerts + status changes since last id; counter polls every 5 s, owner page every 10 s |
| `order_action.php` | staff | accept, ready, serve, pickup, cancel (cancel needs owner PIN after `preparing`) |
| `counter_bill.php` | staff | Save a counter bill |
| `table_action.php` | staff | move order, settle, dismiss alert |
| `stock.php` | staff | Toggle availability |
| `discount_approve.php` | staff + owner PIN | Owner approves a counter discount (amount, reason); kept in the session 10 min, used once by `counter_bill.php` |
| `customer_cancel.php` | public (order key) | Customer cancels their own takeaway order while it is still `received` |
| `place_table_order.php` | public (table QR code) | Table order (takeaway orders use `place_order.php`) |
| `table_status.php?t=` | public (table QR code) | The table's open visit: orders + statuses, running total |
| `table_detail.php?id=` | staff | One table's visit for the Tables tab (orders, alerts, move targets) |
| `bulk_action.php` | staff | Bulk tab: record a payment (advance), ready, complete (balance → bill) |
| `owner_action.php` | owner (password login) | Owner's phone: `accept` (takeaway / table), `cancel` (any open order incl. bulk, reason; the password login is the owner's approval, no PIN), `approve` (bulk, advance in paise) |
| `push_subscribe.php` | owner (password login) | This phone's Web Push subscription: `subscribe` (keeps an existing mute), `unsubscribe`, `mute`, `status`, `test` (test notification to this phone only) |

`table_action.php` also handles `close` (visit with nothing to bill), `reprint` and `cancel_bill` (settled table bill, owner PIN). `order_action.php` handles `serve` and returns the KOT print URL when a table order is accepted.

`poll.php` is also the counter's connection check (the "No internet" banner) and returns 401 when the login has ended; it does not count as activity, so an idle counter still logs out after 12 h. Without `?full=1` it returns only counts (badge + beep); the Online tab asks for the full list. It also returns `kot_pending`: table orders accepted in the last 10 minutes; the counter prints each one's KOT once (printed ids kept in the counter's localStorage), so a table order accepted on the owner's phone still prints at the counter, and one accepted at the counter is not printed twice. `?view=owner` (owner / super-admin with a password login, else 401) adds today's sales, active orders, open bulk orders and open table alerts for the owner's phone.

Rate limits (simple, stored in a `rate_limits` table keyed by IP + action, or in APCu if available): `place_order` max 5 per 10 min per IP and per mobile; `table_alert` max 1 per 30 s per table; login max 5 failures then 15 min lock.

## 7. Real-time without WebSockets

Shared hosting has no WebSockets. Use short polling:

- Counter: `setInterval` 5 s → `poll.php?since=lastId`. On new items: Web Audio beep (two tones, 0.3 s) repeated every 10 s until a staff member taps the alert. No audio files needed.
- Customer status page: 10 s.
- Owner page: 10 s (plus Web Push).
- Pause polling when `document.hidden` on customer pages (not on the counter).

## 8. Printing (Epson TM-T82, 80 mm)

- Print pages live in `order/counter/print.php?type=bill|kot|day&id=…`.
- CSS: `@page { size: 80mm auto; margin: 0; }`, body width 72 mm (printable area), font Noto Sans Devanagari, base 12 px, token and table number 32–40 px bold, black only.
- The counter UI loads the print page in a hidden `<iframe>` and calls `iframe.contentWindow.print()` after the iframe's `load` event (and fonts ready). With Chrome's `--kiosk-printing` flag this prints silently to the Windows default printer.
- Chrome sends the page as an image to the printer driver, so Marathi prints correctly even though the printer has no Devanagari font.
- Keep receipts short: no images except an optional small monochrome logo.

## 9. Web Push (owner's Android phone)

- VAPID keys: `php database/vapid_keys.php`, once per server, pasted into that server's `app/config.php` (never committed). Keep production's keys: new keys silently cut off every subscribed phone until its owner page is opened again (the page then re-subscribes by itself).
- `order/owner/` registers `/sw.js` with scope `/owner/`, asks notification permission on a button tap, posts the subscription to `push_subscribe.php`, and sends it again on every page load (the browser may renew it). Mute is per phone (`push_subscriptions.is_muted`).
- `PushService::notifyOwners($message)` sends to every non-muted subscription of active owners / super-admins (never staff); subscriptions answered with 404/410 are deleted, other failures are logged. A message carries the title and body in **both** languages (`['title' => ['mr' => …, 'en' => …], 'body' => …, 'url' => '/owner/?order=ID', 'tag' => …]`); `sw.js` shows the language the owner page last used on that phone (kept in Cache Storage `mahavir-prefs`, read by the service worker; Marathi if unknown). Notification tap opens / focuses `/owner/` and scrolls to the order; the worker only opens `/owner/` URLs.
- Triggered on: new takeaway order, new table order, new bulk request, a new Request bill (not repeated while the same alert is still open). Sent with `notify_owners_later()`: after the reply (PHP-FPM / LiteSpeed finish the request first), so the customer never waits for the push service; a push failure never breaks order placement (caught + logged).
- `sw.js` caches only the "No internet" page (`owner/offline.php`, both languages) and its two stylesheets. Order data is never cached. Bump `CACHE` in `sw.js` when the offline page changes.
- Requires HTTPS (or `localhost` / `127.0.0.1` for local testing in desktop Chrome).

## 10. Browser rules

### Counter pages and print pages: Chrome 109 (Windows 7)

Allowed: CSS grid/flex, custom properties, `:has()`, `gap`, `aspect-ratio`, `<dialog>`, `fetch`, `async/await`, ES2022 classes, optional chaining, `structuredClone`, Web Audio.

**Do not use** (newer than Chrome 109): CSS nesting, `color-mix()`, `@scope`, subgrid, `text-wrap: balance`, Popover API (`popover` attribute), View Transitions, `Array.prototype.toSorted/toReversed/with`, `Object.groupBy`, `Promise.withResolvers`, `Array.fromAsync`, `:user-valid`. When unsure, check caniuse for Chrome 109.

Touch: buttons ≥ 56 px tall on the counter, ≥ 44 px elsewhere; no hover-only actions; prevent double-tap submit (disable the button until the request returns); large readable text (≥ 16 px).

### Customer, owner and website pages

Target current Android Chrome and iOS Safari; still avoid the list above to keep one style of code. Mobile-first, works at 360 px width.

## 11. Security checklist

- PDO prepared statements only; no string-built SQL with user input.
- `e()` on every output; JSON via `json_encode` with `JSON_HEX_TAG|JSON_HEX_AMP`.
- CSRF on all POSTs.
- `password_hash()` / `password_verify()` for PINs and passwords; regenerate session id on login.
- Order status links carry a random 32-char `order_key`; table QR carries a random 32-char `qr_token`; never sequential ids alone.
- Validate mobile (`^[6-9][0-9]{9}$`), names (1–60 chars), quantities (1–50 for normal orders; up to 999.99 for bulk), notes (≤ 200 chars).
- Server recalculates every price and total; never trust prices from the browser.
- Owner-only actions re-check role on the server.
- `app/`, `storage/`, `database/`, `cron/`, `tests/`, `vendor/` are never web-accessible (they are outside the web roots).
- HTTP security headers in a shared header function: `X-Content-Type-Options: nosniff`, `Referrer-Policy: same-origin`, `X-Frame-Options: SAMEORIGIN`, a basic Content-Security-Policy (self + Google Maps embed on the location page).
- Uploads: allow jpg/png/webp only, check MIME with `finfo`, re-encode with GD, random file names.

## 12. Testing

- PHPUnit (`tools/phpunit.phar`), config `phpunit.xml` at repo root, tests in `tests/`.
- Test database `mahavir_test` (created by `tests/bootstrap.php` from migrations + seed; reset between test classes).
- Required test coverage:
  - `PricingService`: subtotal, parcel charge rules per order type, discount, paise rounding.
  - `CartService`: rejects sold-out, inactive, ₹0, wrong prices, bad quantities.
  - `SlotService`: earliest slot, last slot, closed hours, capacity full.
  - `SequenceService`: daily token reset, no duplicate token/bill numbers under repeated calls, bill numbers continuous.
  - `OrderService`: allowed and forbidden status transitions per order type; cancel rules.
  - `TableService`: session opens on first order, running total, move order, settlement creates one bill number and closes session.
  - `CustomerService`: no-show count and blocking.
  - Validation helpers (mobile, name, quantity).
- UI is checked manually with the checklist in each milestone of `BUILD_PLAN.md`.

## 13. Logging and backups

- App log: `storage/logs/app-YYYY-MM-DD.log` (errors, push failures, auth failures).
- `audit_log` table: cancellations, discounts, price changes, settings changes, stock toggles, staff changes.
- `cron/backup.php`: nightly `mysqldump` (via `exec`, gzip) to `storage/backups/`, keep 30 days. If `exec` is disabled on the host, fall back to a PHP-based dump of all tables.
